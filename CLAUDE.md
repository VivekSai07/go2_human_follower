# Claude guidance — Go2 Human Follower

Read [AGENTS.md](AGENTS.md) first. It is the canonical current guide for this repository; [architecture](docs/ARCHITECTURE.md) maps the running components, and [README.md](README.md) contains setup and calibration instructions. Check the code when a document conflicts with the implementation. The historical [implementation plan](docs/superpowers/plans/2026-11-23-go2-follower.md) is not a substitute for current source.

This is a personal, public ROS 2 Humble Go2 follower repository. Keep its code and deployment self-contained with public dependencies and interfaces. The ROS-independent logic lives in `src/go2_follower_perception` and `src/go2_follower_control`; ROS nodes wrap that logic. The camera adapter publishes `/go2/camera/image_raw`, the LiDAR adapter publishes `/follower/cloud_base` and `/follower/scan`, perception publishes `/follower/target`, and control alone publishes live `/cmd_vel`.

Treat this as an **off-robot prototype** until the Jetson build, model, topic QoS, sensor extrinsics, stop behavior, and corridor tests are measured on hardware. The YAML calibration is a placeholder and `calibration_verified` starts false. Never enable live movement by changing that flag without operator-provided measurements. A zero velocity command is not a physical emergency stop.

For a change, inspect Git status and the relevant source, run `python3 -m pytest tests -q`, then run the ROS build and Docker checks if those tools are available. State which checks could not run. Keep model weights, bags, secrets, and proprietary code out of Git. Update `AGENTS.md`, the architecture, and the README if interfaces or verification status change. Commit or push only when the user requests it, using a personal author identity and no AI co-author trailer.
